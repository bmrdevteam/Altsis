# 권한 설정 🔵

Altsis는 학기별로 세분화된 권한 시스템을 제공합니다. 수업 개설, 수강신청, 평가의 3대 핵심 권한은 학기 단위입니다. AI 역할 권한·지침은 **학교 AI 탭**에서 관리하고, 학기 **AI 설정** 탭은 그 학기에서 AI를 켤지 끌지만 정합니다.

## 권한 시스템 개요

### 학기별 3대 권한

학기(Season) 단위로 다음 세 가지 핵심 권한을 설정합니다.

| 권한 | 필드명 | 설명 |
|------|--------|------|
| 수업 개설 권한 | `permissionSyllabusV2` | 누가 수업(강의계획서)을 만들 수 있는지 설정 |
| 수강신청 권한 | `permissionEnrollmentV2` | 누가 수강신청을 할 수 있는지 설정 |
| 평가 권한 | `permissionEvaluationV2` | 누가 평가를 입력할 수 있는지 설정 |

### 권한 데이터 구조

각 권한은 동일한 구조를 공유합니다.

```json
{
  "permissionSyllabusV2": {
    "teacher": false,
    "student": false,
    "exceptions": [
      {
        "registration": "65a1b2c3d4e5f6a7b8c9d0e1",
        "role": "teacher",
        "user": "65a1b2c3d4e5f6a7b8c9d0e2",
        "userId": "teacher01",
        "userName": "김교사",
        "isAllowed": true
      }
    ]
  }
}
```

| 필드 | 설명 | 기본값 |
|------|------|--------|
| `teacher` | 교사 전체에 대한 기본 권한 | `false` |
| `student` | 학생 전체에 대한 기본 권한 | `false` |
| `exceptions` | 개별 사용자 예외 목록 | `[]` |

### 권한 적용 흐름

```
학기(Season) 권한 설정
    │
    ├── teacher: true/false (교사 전체)
    ├── student: true/false (학생 전체)
    └── exceptions: 개별 예외
         │
         └── 각 Registration에 최종 권한 계산하여 저장
              ├── registration.permissionSyllabusV2 = true/false
              ├── registration.permissionEnrollmentV2 = true/false
              └── registration.permissionEvaluationV2 = true/false
```

> [!IMPORTANT]
> 학기 수준에서 권한을 변경하면, 해당 학기에 등록된 모든 Registration의 권한 필드가 자동으로 재계산됩니다. 각 사용자의 역할(role)과 예외 설정(exceptions)을 기반으로 최종 권한이 결정됩니다.

## 수업 개설 권한

> **필드명**: `permissionSyllabusV2`
>
> **필요 권한**: 🔵 Manager

수업 개설 권한은 누가 새로운 수업(강의계획서, Syllabus)을 만들 수 있는지를 결정합니다.

### 설정 옵션

| 설정 | 교사 | 학생 | 결과 |
|------|:----:|:----:|------|
| 교사: Y, 학생: N | O | X | 교사만 수업 생성 가능 (가장 일반적) |
| 교사: Y, 학생: Y | O | O | 교사와 학생 모두 수업 생성 가능 |
| 교사: N, 학생: N | X | X | 아무도 수업 생성 불가 (관리자만 가능) |
| 교사: N, 학생: Y | X | O | 학생만 수업 생성 가능 (특수 상황) |

### 설정 절차

1. 학기 상세 페이지에서 **권한** 탭으로 이동합니다.
2. 권한 목록 테이블에서 **수업 개설 권한** 행을 확인합니다.
3. **선생님** 열의 Y/N 버튼을 클릭하여 교사 권한을 토글합니다.
   - `Y` (녹색): 허용
   - `N` (적색): 거부
4. **학생** 열의 Y/N 버튼을 클릭하여 학생 권한을 토글합니다.
5. 필요한 경우 **설정** 버튼을 클릭하여 개별 예외를 추가합니다.

### 운영 시나리오

| 시나리오 | 교사 | 학생 | 예외 | 설명 |
|----------|:----:|:----:|------|------|
| 일반 학교 | Y | N | 없음 | 교사가 수업을 만들고 학생이 수강 |
| 학생 자치 수업 | Y | Y | 없음 | 교사와 학생 모두 수업 생성 가능 |
| 관리자 통제 | N | N | 특정 교사만 Y | 지정된 교사만 수업 생성 가능 |
| 수업 개설 기간 종료 | N | N | 없음 | 수업 개설 마감 후 전체 차단 |

## 수강신청 권한

> **필드명**: `permissionEnrollmentV2`
>
> **필요 권한**: 🔵 Manager

수강신청 권한은 누가 수강신청(Enrollment)을 할 수 있는지를 결정합니다.

### 설정 옵션

| 설정 | 교사 | 학생 | 결과 |
|------|:----:|:----:|------|
| 교사: N, 학생: Y | X | O | 학생만 수강신청 가능 (가장 일반적) |
| 교사: Y, 학생: Y | O | O | 교사와 학생 모두 수강신청 가능 |
| 교사: N, 학생: N | X | X | 수강신청 마감 (아무도 신청 불가) |
| 교사: Y, 학생: N | O | X | 교사가 학생 대신 수강신청 |

### 설정 절차

1. 학기 상세 페이지에서 **권한** 탭으로 이동합니다.
2. **수강신청 권한** 행에서 교사/학생 권한을 설정합니다.
3. 필요한 경우 **설정** 버튼으로 개별 예외를 추가합니다.

### 운영 시나리오

| 시나리오 | 교사 | 학생 | 예외 | 설명 |
|----------|:----:|:----:|------|------|
| 수강신청 기간 | N | Y | 없음 | 학생이 직접 수강신청 |
| 수강신청 마감 | N | N | 없음 | 수강신청 기간 종료 후 차단 |
| 교사 조정 기간 | Y | N | 없음 | 교사가 학생 수강을 조정 |
| 특정 학생만 허용 | N | N | 해당 학생 Y | 추가 수강신청 필요한 학생만 허용 |

> [!TIP]
> 수강신청 기간을 운영하려면, 기간 시작 시 학생 권한을 `Y`로 변경하고, 기간 종료 시 `N`으로 변경하세요. 권한 변경은 즉시 적용되므로 별도의 기간 설정 없이 수동으로 관리할 수 있습니다.

## 평가 권한

> **필드명**: `permissionEvaluationV2`
>
> **필요 권한**: 🔵 Manager

평가 권한은 누가 평가 데이터를 입력할 수 있는지를 결정합니다. 이 권한은 학기 수준의 전체 평가 입력 가능 여부를 제어하며, 개별 평가 항목의 세부 권한(`authOption`)과 함께 작동합니다.

### 설정 옵션

| 설정 | 교사 | 학생 | 결과 |
|------|:----:|:----:|------|
| 교사: Y, 학생: N | O | X | 교사만 평가 입력 가능 (가장 일반적) |
| 교사: Y, 학생: Y | O | O | 교사와 학생 모두 평가 입력 가능 |
| 교사: N, 학생: N | X | X | 평가 입력 마감 (아무도 입력 불가) |

### 설정 절차

1. 학기 상세 페이지에서 **권한** 탭으로 이동합니다.
2. **평가 권한** 행에서 교사/학생 권한을 설정합니다.
3. 필요한 경우 **설정** 버튼으로 개별 예외를 추가합니다.

### 평가 권한의 이중 구조

평가 입력은 두 단계의 권한 검사를 거칩니다.

```
1단계: 학기 수준 권한 (permissionEvaluationV2)
    │
    └── 사용자가 평가 기능에 접근 가능한지 확인
         │
         └── 2단계: 항목 수준 권한 (formEvaluation.authOption)
              │
              └── 해당 평가 항목을 편집/열람 가능한지 확인
```

| 단계 | 필드 | 범위 | 설명 |
|------|------|------|------|
| 1단계 | `permissionEvaluationV2` | 학기 전체 | 평가 기능 접근 가능 여부 |
| 2단계 | `formEvaluation[].authOption` | 항목별 | 개별 평가 항목의 편집/열람 권한 |

#### 1단계 + 2단계 조합 예시

| 학기 권한 (교사) | 항목 권한 (`authOption`) | 결과 |
|:----------------:|:------------------------:|------|
| Y | `editByTeacher` | 교사가 해당 항목 편집 가능 |
| Y | `editByStudent` | 교사는 해당 항목 편집 불가 (학생 전용) |
| Y | `editByTeacherAndStudentCanView` | 교사가 편집, 학생은 열람 |
| N | `editByTeacher` | 교사도 편집 불가 (학기 권한 차단) |

> [!WARNING]
> 학기 수준의 평가 권한(`permissionEvaluationV2`)이 `N`이면, 항목 수준 권한(`authOption`)에 관계없이 해당 역할의 평가 입력이 전부 차단됩니다. 평가 기간이 종료되면 학기 수준에서 권한을 `N`으로 변경하여 전체 마감할 수 있습니다.

## AI 권한

> **학교**: `School.aiConfig.permission` (지침 라이브러리·스킬은 학교 AI 탭)
> **학기**: `Season.aiSettings.enabled` (그 학기 on/off만)
>
> **필요 권한**: 🔵 Manager

AI를 쓰려면 다음이 모두 충족되어야 합니다.

```
아카데미 AI 활성화 (aiEnabled) + API 키 (플랜/소유자)
    └── 학교 AI 탭: 기능 켜기, 교사/학생 권한, 라이브러리·스킬
         └── 학기 AI 설정 탭: 해당 학기 enabled
```

| 단계 | 설정 | 어디서 |
|------|------|--------|
| 1 | 아카데미 AI + 키·모델 | 소유자 아카데미 / Admin **플랜** |
| 2 | 학교 권한·지침 | **관리 → 학교 → AI** |
| 3 | 학기에서 사용 | 학기 상세 **AI 설정** (켜기/끄기만) |

학교 AI 탭에서 교사·학생 토글로 Alter 사용 여부를 정합니다. 지침·학습정보 라이브러리 항목을 스킬(챗봇, 수업, 평가, 기록, 문서, 문서 점검, 응답, 활동, 양식, 검색 등)에 연결합니다.

학기 탭 UI 안내: 「지침·라이브러리·역할 권한은 학교 설정의 AI 탭에서 관리합니다.」

> [!TIP]
> 미성년 보호·일일 Alt 한도는 [아카데미 관리 — AI](academy-management.md#ai-설정)와 학교 AI 탭의 이행사항 체크리스트를 따릅니다.

## 예외 사용자 설정

3대 권한(수업 개설, 수강신청, 평가) 각각에 대해 개별 사용자 예외를 설정할 수 있습니다.

### 예외 설정 개념

기본 권한(teacher/student)으로 역할 전체의 허용/거부를 설정한 후, 예외(exceptions)로 특정 사용자만 다르게 설정합니다.

```
기본 권한: teacher = true (교사 전체 허용)
    │
    ├── 김교사: 기본 권한 적용 → 허용
    ├── 이교사: 기본 권한 적용 → 허용
    └── 박교사: 예외 설정 (isAllowed: false) → 거부
```

### 예외 데이터 구조

| 필드 | 설명 |
|------|------|
| `registration` | 대상 Registration의 ObjectId |
| `role` | 사용자 역할 (`teacher` / `student`) |
| `user` | 사용자 ObjectId |
| `userId` | 사용자 ID |
| `userName` | 사용자 이름 |
| `isAllowed` | 허용 여부 (`true`: 허용, `false`: 거부) |

### 최종 권한 계산 로직

각 Registration의 최종 권한은 다음 로직으로 계산됩니다.

```
1. 사용자가 exceptions 목록에 포함되어 있는가?
   ├── YES → exceptions의 isAllowed 값을 사용
   └── NO → role에 해당하는 기본 권한(teacher/student) 값을 사용
```

| 역할 | 기본 권한 | 예외 설정 | 최종 결과 |
|------|:---------:|:---------:|:---------:|
| teacher | `true` | 없음 | **허용** |
| teacher | `true` | `isAllowed: false` | **거부** |
| teacher | `false` | 없음 | **거부** |
| teacher | `false` | `isAllowed: true` | **허용** |
| student | `true` | 없음 | **허용** |
| student | `false` | `isAllowed: true` | **허용** |

### 예외 설정 절차

1. 학기 상세 페이지 > **권한** 탭에서 대상 권한의 **설정** 버튼을 클릭합니다.
2. 예외 설정 팝업이 표시됩니다.
3. 학기에 등록된 사용자 목록이 표시됩니다.
4. 예외를 적용할 사용자를 찾습니다.
5. 해당 사용자의 **허용/거부** 상태를 변경합니다.
6. **저장** 버튼을 클릭합니다.

### 예외 설정 실전 예시

#### 예시 1: 특정 교사만 수업 개설 허용

> 교장, 교감만 수업을 개설할 수 있도록 설정

```
수업 개설 권한:
  teacher: false (교사 전체 거부)
  student: false (학생 전체 거부)
  exceptions:
    - 교장선생님: isAllowed = true
    - 교감선생님: isAllowed = true
```

#### 예시 2: 수강신청 추가 마감 후 특정 학생만 허용

> 수강신청이 마감되었지만 전학생에게 추가 수강신청을 허용

```
수강신청 권한:
  teacher: false
  student: false (마감 상태)
  exceptions:
    - 전학생(홍길동): isAllowed = true
```

#### 예시 3: 특정 교사의 평가 입력 차단

> 대부분의 교사는 평가 가능하지만, 특정 교사의 평가를 일시 차단

```
평가 권한:
  teacher: true (교사 전체 허용)
  student: false
  exceptions:
    - 박교사: isAllowed = false (일시 차단)
```

## 권한 관리 요약 표

| 권한 | 필드명 | 일반 설정 | 주요 용도 |
|------|--------|-----------|-----------|
| 수업 개설 | `permissionSyllabusV2` | 교사: Y, 학생: N | 교사가 수업 만들기 |
| 수강신청 | `permissionEnrollmentV2` | 교사: N, 학생: Y | 학생이 수강신청 |
| 평가 | `permissionEvaluationV2` | 교사: Y, 학생: N | 교사가 평가 입력 |
| AI 사용 | `School.aiConfig.permission` (학기 on/off는 `Season.aiSettings.enabled`) | 교사: Y, 학생: N | 교사가 Alter 활용 |

## 학기 운영 기간별 권한 설정 가이드

| 운영 기간 | 수업 개설 | 수강신청 | 평가 | AI |
|-----------|:---------:|:--------:|:----:|:---:|
| 학기 준비 | 교사: Y | N / N | N / N | 교사: Y |
| 수강신청 기간 | N / N | 학생: Y | N / N | 교사: Y |
| 수업 운영 | N / N | N / N | 교사: Y | 교사: Y |
| 평가 기간 | N / N | N / N | 교사: Y, 학생: Y | N / N |
| 학기 종료 | N / N | N / N | N / N | N / N |

> [!TIP]
> 위 표는 일반적인 운영 시나리오의 예시입니다. 각 학교의 운영 방식에 맞게 권한을 조정하세요. 권한 변경은 즉시 적용되므로, 운영 기간 전환 시 관리자가 직접 변경해야 합니다.
